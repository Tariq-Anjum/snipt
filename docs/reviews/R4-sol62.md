## Blockers

1. **Restore still conflates distinct messages.** Two archive rows with different IDs, the same sender, timestamp, body and direction, and different SIM slots collapse into one row even on an empty restore. The second lookup sees the row inserted earlier in the same transaction. The SQLite probe exercised the actual dedup predicate. Archive flags can also follow the first local thread for a sender while a matching message belongs to another thread. Preserve multiplicity, match on transport and SIM where available, and derive thread mappings from the matched rows or reject ambiguous mappings. [Thread selection](/mnt/MD/AI-tools/mySMS/crates/sms-store/src/restore.rs:137) · [Dedup and reference remap](/mnt/MD/AI-tools/mySMS/crates/sms-store/src/restore.rs:177)

2. **A valid archive can permanently stop new SMS ingestion and sends.** Restoring a message ID of `9007199254740991` records `9007199254740992` as the next ID. The SQLite probe confirmed the watermark survives deletion. Every subsequent message allocation fails. The thread cap has the same failure mode for new conversations. Remap external IDs before they can exhaust the local allocator, and handle saturated legacy stores during migration. [Validation](/mnt/MD/AI-tools/mySMS/crates/sms-store/src/restore.rs:56) · [Explicit-ID insert](/mnt/MD/AI-tools/mySMS/crates/sms-store/src/ingest.rs:143) · [Allocation cap](/mnt/MD/AI-tools/mySMS/crates/sms-store/src/ids.rs:58)

3. **The notification target can still change after posting.** The v1 migration creates empty ID counters. Deleting legacy maxima `1002` and `102` before the first v2 allocation reissued both IDs in the SQLite probe. On v2, restore can reclaim retired IDs even with a populated counter, so an old action can match a different restored message from the same sender. A separate pre-existing collision survives the fix: thread IDs `101` and `536871013` produce distinct notifications but the same Reply request code `809`. `FLAG_UPDATE_CURRENT` replaces the older action’s extras with the newer target, which then passes validation. Seed the counters in migration, remap retired explicit IDs, and key actions by full message identity and action in the intent data. [Migration](/mnt/MD/AI-tools/mySMS/crates/sms-store/src/schema.rs:115) · [Restore ID reuse](/mnt/MD/AI-tools/mySMS/crates/sms-store/src/restore.rs:199) · [PendingIntent](/mnt/MD/AI-tools/mySMS/plugins/tauri-plugin-telephony/android/src/main/java/app/snipt/telephony/Notifier.kt:77)

4. **Android send state can diverge from the radio and provider.** Delete a queued message after `beginSend` and before provider binding. The SQLite probe confirmed the delete cascades to the attempt. The sender then continues after `bindSend` returns false, leaving a radio send and an OUTBOX row without a callback target. Separately, a callback can commit `sent`, pause, and write provider `SENT` after another callback commits `failed` and writes provider `FAILED`. Serialize deletion against handoff, abort and clean up on rejected binding, and serialize or version-check provider status writes. On upgrade, move legacy in-flight sends to an explicit indeterminate state without resending. The migration probe left a v1 `sending` row with zero attempts, and the receiver ignores callbacks with the old extras. [Sender](/mnt/MD/AI-tools/mySMS/plugins/tauri-plugin-telephony/android/src/main/java/app/snipt/telephony/SmsSender.kt:64) · [Callback receiver](/mnt/MD/AI-tools/mySMS/plugins/tauri-plugin-telephony/android/src/main/java/app/snipt/telephony/SmsStatusReceiver.kt:35) · [Attempt foreign key](/mnt/MD/AI-tools/mySMS/crates/sms-store/src/schema.rs:117)

5. **Replay can resurrect a locally deleted SMS and permanently omit a legacy receipt.** If a spam SMS arrives just after a provider snapshot and cleanup deletes it before Rust applies that snapshot, reconciliation prunes the new tombstone because the older snapshot lacks the provider ID. The next eligible pass reimports it. The SQLite probe reproduced the prune and subsequent missing-row lookup. On upgrade, a missed provider inbox row `21` is permanently excluded if row `22` was already ingested. Snapshot tombstones before querying or recheck provider absence before pruning. Provide an explicit recovery path for ambiguous pre-v2 rows, since v1 stored no deletion history. [Local cleanup](/mnt/MD/AI-tools/mySMS/src-tauri/src/core.rs:799) · [Prune and replay](/mnt/MD/AI-tools/mySMS/crates/sms-store/src/platform.rs:690) · [Legacy floor](/mnt/MD/AI-tools/mySMS/crates/sms-store/src/schema.rs:137)

6. **Android vault protection fails open while capabilities are pending.** The UI starts with `platform: 'linux'`. Vault data loads independently, and `acquireVaultSecure` treats that placeholder as successful acquisition without invoking Android. The in-memory Node test verified both that branch and the correctly gated branch after Android is known. Keep Reveal and sensitive Copy disabled until native platform detection completes, then require confirmed `FLAG_SECURE` for Reveal. [Capabilities load](/mnt/MD/AI-tools/mySMS/src/App.tsx:154) · [Independent vault fetch](/mnt/MD/AI-tools/mySMS/src/App.tsx:410) · [Secure acquisition](/mnt/MD/AI-tools/mySMS/src/api/telephony.ts:67)
