# mySMS — Architecture (v1)

Author: Opus (architect). Date: 2026-11-22. Status: plan, not implemented.
Labels: **[F]** fact verified in this session (command/URL given) · **[I]** inference · **[R]** recommendation · **[U]** uncertainty / must be verified by a slice.

## 1. Decision: Tauri 2 confirmed (not overturned)

**[R] Keep Tauri 2 (stable 2.12.x): one Rust core + the existing React UI in the system webview, on Android (WebView/Chromium) and Linux (WebKitGTK).**

Evidence:
- [F] Tauri 2 stable is current and active: crates.io `tauri` max_stable 2.12.7 (2026-11-18), `tauri-cli` 2.12.6, `wry` 0.57.3; GitHub tauri-apps/tauri Apache-2.0, pushed 2026-11-21.
- [F] Tauri mobile plugins are Kotlin classes (`@TauriPlugin`, `@Command`, `load(webView)`, `onNewIntent`) — v2.tauri.app/develop/plugins/develop-mobile. This is exactly the surface needed for RoleManager / SmsManager / receivers / SAF.
- [F] The `tauri-cli` 2.12.6 Android template pins AGP 9.3.1, Kotlin 2.2.10, Gradle 9.6.1, compileSdk/targetSdk 37 (raw template files at tag `tauri-cli-v2.12.6`).
- [F] Linux runtime dependency is already present: `webkit2gtk-4.1 2.54.3`, `gtk3`, `librsvg`, `openssl` (pacman -Q). GPU: AMD Phoenix1 iGPU, Hyprland/Wayland.
- [F] Rust target `aarch64-linux-android` already installed (`rustup target list --installed`).

Why not the alternatives:
- Compose (Android) + Slint/GTK (Linux): two UIs, violates the owner's "ONE app, shared UI" decision and discards ~200 KB of approved React UI. [I]
- Slint for both: no reuse of React UI; Slint licence is GPLv3 / royalty-free / commercial (batisseur `linux-desktop-gui` pack notes it) — owner forbids GPL in the shipped app; royalty-free terms would need review. [F for pack note, I for fit]
- Dioxus/other webview shells: same webview trade-offs as Tauri with a smaller Android plugin ecosystem. [I]
- **Tauri 3** exists only as `3.0.0-alpha.6` on crates.io [F]. **[R] Do not adopt the alpha**; pin 2.12.x exactly.

Known costs accepted: webview `backdrop-filter` cost on mid-range phones (handled in UI-PLAN.md), and Tauri plugins are bound to the Activity/WebView — so background SMS receipt needs a direct JNI path (§6.3).

## 3. TS engine → Rust crate mapping

| TS module (src/engine) | Rust target | Notes |
|---|---|---|
| types.ts | sms-types | `#[serde(rename_all="camelCase")]`, optional fields `skip_serializing_if = "Option::is_none"`, `SenderKind` as `#[serde(tag="type")]` |
| dlt.ts, otp.ts, finance.ts, reminder.ts | sms-engine::{dlt,otp,finance,reminder} | regex crate; see parity hazards |
| ml.ts | sms-engine::ml | FNV-1a, 8192-dim hashed features, heuristic weights in `OnceLock` |
| thread.ts, index.ts (SmsEngine) | sms-engine::{thread,engine} | identical cascade order |
| budget.ts, cleanup.ts | sms-engine::{budget,cleanup} | local-time windows take explicit `tz_offset_min` |
| translate.ts | sms-engine::translate | rule/phrasebook translator, ported 1:1 (16 KB of tables) |
| store.ts | sms-store | in-memory `buildThreads` semantics re-expressed as SQL + incremental thread table |
| indexedDb.ts | sms-store (SQLite) + sms-testdata (generator) | IndexedDB removed |
| backup.ts, cryptoVault.ts | sms-crypto | format-compatible envelope |
| seedData.ts | sms-testdata | dev/test only |

Parity hazards (must be covered by fixture tests):
- [F] `fnv1a32` hashes `charCodeAt(i) & 0xff` (UTF-16 code unit, low byte), **not UTF-8 bytes**. Rust must iterate `s.encode_utf16()` and use `u as u8`.
- [F] `ml.ts` uses `getUTCHours()` (timezone-free); `budget.ts getCycleWindow` and `buildBackupFilename` use **local time** (`new Date(y,m,d)`). [R] Rust takes `tz_offset_min` from the OS (Android `TimeZone.getDefault()`, Linux `chrono::Local`) and fixtures are generated with `TZ=Asia/Kolkata`.
- [I] JS `\b` is ASCII; Rust `regex` `\b` is Unicode by default → use `(?-u:\b)` in ported patterns. JS `/i` vs Rust Unicode case folding can differ on non-ASCII; patterns are ASCII + `₹`. [F] No lookahead/backreferences exist in the TS regexes (grep).
- [I] `Math.sin`/softmax floats may differ in the last ulp → compare scores with 1e-9 tolerance, categories/reasons exactly.
- [F] JS `String.prototype.trim()` strips U+FEFF; Rust `str::trim` does not. Backup passphrase trimming must use the JS whitespace set.

## 4. Storage (sms-store)

- [F] `rusqlite 0.43.0` (depends on `libsqlite3-sys ^0.40.0`). [F] `libsqlite3-sys` bundled build sets `-DSQLITE_ENABLE_FTS5` (verified in 0.38.2 build.rs); [U] re-verify in 0.40 with a `CREATE VIRTUAL TABLE … USING fts5` test in S6.
- Features: `rusqlite = { version = "=0.43.0", features = ["bundled"] }` — same SQLite on Android and Linux, no system lib.
- Pragmas: `journal_mode=WAL`, `synchronous=NORMAL`, `foreign_keys=ON`, `busy_timeout=3000` (two connections exist on Android: Tauri state + JNI receiver).
- Every read-modify-write transaction is `BEGIN IMMEDIATE` (`sms_store::write_tx`): a deferred transaction that reads first cannot upgrade after the other connection commits (`SQLITE_BUSY_SNAPSHOT`). Migrations read `user_version` and apply under the same immediate lock; `journal_mode=WAL` is retried up to the busy timeout because a concurrent first open can get SQLITE_BUSY without the busy handler. Regression: `crates/sms-store/tests/concurrency.rs`.
- Schema (v1, `PRAGMA user_version=1`, forward-only migrations in code):
  - `messages(id INTEGER PRIMARY KEY, provider_id INTEGER UNIQUE, provider_kind TEXT, thread_id INTEGER, sender TEXT, contact_name TEXT, body TEXT, ts_ms INTEGER, is_known_contact INT, is_outgoing INT, sim_slot INT, sub_id INT, is_read INT, is_starred INT, protocol TEXT, rcs_status TEXT, rcs_card_json TEXT, category TEXT, confidence REAL, reason TEXT, scores_json TEXT, otp_json TEXT, txn_json TEXT, reminder_json TEXT, lang TEXT, send_status TEXT)`
  - indexes: `(thread_id, ts_ms DESC, id DESC)`, `(category, ts_ms DESC)`, `(ts_ms DESC, id DESC)`.
  - `threads(thread_id PK, latest_ts, latest_msg_id, sender, display_name, sender_kind_json, category, confidence, unread, has_starred, is_archived, is_blocked, sim_slot, is_rcs)` — maintained incrementally on ingest/delete/read (thread consensus recomputed for the touched thread only).
  - `transactions(msg_id PK, ts_ms, amount, direction, method, last4, merchant, ref_id, balance, budget_category)`; `reminders_done(msg_id PK)`; `blocked_senders(sender PK)`; `settings(key PK, json)`; `meta(key PK, value)` (provider sync high-water marks, last weekly scan).
  - `messages_fts USING fts5(body, sender, contact_name, content='messages', content_rowid='id', tokenize='trigram')` + triggers. [R] trigram because TS search is token-AND **substring** matching (`haystack.includes(tok)`, store.ts); tokens <3 chars fall back to `LIKE` on `threads`.
- Schema v2 (R2/R3 review): `id_alloc` (persistent message/thread id high-water marks; ids never reused, bounded to 1..=2^53-1), `send_attempts` + `send_part_results` (per-attempt provider binding, persisted per-part results, monotonic send state), `provider_tombstones` + `meta.provider_replay_floor` (reconcile replay). Restore = `Store::restore_merge` (validated, atomic, identity-based dedup, id remapping).
- Paging: keyset cursors `(latest_ts, thread_id)` for thread list and `(ts_ms, id)` for messages; page size 50; never `OFFSET`.
- Capacity target: 10,000 seed messages ingest+classify ≤ 2 s on x86_64 debug-free release build; thread page query ≤ 5 ms; FTS query ≤ 20 ms [R targets, measured in S6].
- [I] 10k × ~150 B bodies ≈ 1.5 MB text; trigram index adds a few MB — acceptable.
- Android DB: app-private `filesDir` (sandboxed); `android:allowBackup="false"` + data-extraction rules excluding everything (the encrypted `.mysms.enc` is the only backup path). Linux DB: `$XDG_DATA_HOME/<identifier>/snipt.db`, mode 0600 (created/tightened before SQLite opens it, so `-wal`/`-shm` inherit 0600; app dir 0700; `sms_store::fsperm`). [U] At-rest DB encryption (SQLCipher) deferred: adds OpenSSL/licence surface; owner decision.

## 5. Crypto and backup compatibility (sms-crypto)

Pins [F crates.io]: `aes-gcm =0.11.1`, `pbkdf2 =0.13.0`, `sha2 =0.11.1`, `hmac =0.13.0`, `zeroize =1.9.2`, `base64 =0.23.1`, `getrandom =0.4.3`. [U] these are the new RustCrypto generation; co-compilation is verified by `cargo build` in S5, fall back to the previous matched set only with evidence.

`.mysms.enc` v1 compatibility (from backup.ts) [F]:
- Envelope JSON: `format:"mySMS-encrypted-backup-v1"`, `cipher:"AES-256-GCM"`, `kdf:"PBKDF2-SHA256"`, `iterations`, `createdAtMs`, `provider`, `messageCount`, `saltB64` (16 B), `ivB64` (12 B), `ciphertextB64`.
- Key = PBKDF2-HMAC-SHA256(trimmed passphrase UTF-8, salt, iterations, 32 B). Ciphertext = WebCrypto AES-GCM output = ciphertext‖16-byte tag, which is the same layout `aes-gcm` produces. Base64 = standard alphabet with padding (`btoa`).
- Plaintext = `JSON.stringify(MySmsBackupPayload)` (camelCase, `schemaVersion:1`, `app:"mySMS"`).
- Reader rules identical to TS: reject wrong format/missing fields; iterations `< 10_000` → use 150 000; **[R] also cap at 10 000 000** (DoS guard); GCM failure → "Incorrect passphrase or tampered backup file."; unknown JSON fields ignored.
- Writer: create rejects trimmed passphrase < 6 chars. **[R] Rust writer uses 600 000 iterations** (OWASP's PBKDF2-HMAC-SHA256 guidance, [I] from prior knowledge) — the format already records `iterations`, and the TS reader honours it, so this stays v1-compatible. If S5 measures > 1.5 s on the arm64 emulator, drop to 310 000 and record it.
- **[R] KDF choice: PBKDF2 stays for v1.** Argon2id (`argon2 0.6.0` exists [F]) cannot be read by the TS/WebCrypto prototype and would fork the format; reserve it for a future `-v2` envelope only if the owner wants it.
- **[R1 fix] KDF implementation:** `sms-crypto/src/kdf.rs` (PBKDF2-HMAC-SHA256, 32 B) replaces the `pbkdf2::pbkdf2_hmac` call because pinned `hmac 0.13.0`/`pbkdf2 0.13.0` leave the padded key block and the last `U_i` unwiped. It wipes K0/ipad/opad, `U_i`, inner digests and every `sha2` hasher (`zeroize` feature, compile-time `ZeroizeOnDrop` guard). Byte identity: RFC 7914 vectors, equality with the `pbkdf2` crate (now a dev-dependency) and the TS-written v1 fixture; node cross-check decrypts Rust output. Cost on this machine: 600k rounds ≈ 97 ms (was ≈ 51 ms). Not wiped: compiler move/spill copies and buffers owned by the caller.
- **Passphrase ownership:** backup APIs borrow `&str` and never retain it; the caller owns and must wipe its buffer (e.g. `Zeroizing<String>`). Open item outside sms-crypto: the Tauri commands (`src-tauri/src/commands/mod.rs`) receive the passphrase as a plain `String` from IPC and do not wipe it.
- Cross-compat tests both ways in S5: TS-made fixture → Rust decrypt; Rust-made file → `scripts/backup-xcheck.ts` decrypt under node.

OTP vault: AES-256-GCM per item with a 32-byte data key (DEK) held in `Zeroizing`. Android: the DEK is wrapped by a non-exportable Android Keystore AES key (Kotlin `wrapKey`/`unwrapKey` commands); Rust never sees the Keystore key. Linux: ephemeral per-session DEK (same as the TS prototype); backups carry raw SMS only, so nothing extra to protect. [R]

## 6. Android integration (Kotlin plugin `tauri-plugin-telephony`)

### 6.3 Background path (no WebView running)
`SmsDeliverReceiver` (uses `goAsync`): write row to `Telephony.Sms.Inbox` → `System.loadLibrary("mysms_lib")` → JNI `NativeCore.ingest(json): String` (Rust opens the same SQLite via WAL, classifies, stores, returns `{category, otp, threadId, notify}`) → post notification → if the UI is alive, `trigger("smsReceived")`.
- [R] JNI via `jni =0.22.4` (Apache-2.0/MIT, [F] crates.io + GitHub) with a 3-function JSON surface (`init(dbPath)`, `ingest`, `analyze`), compiled into the app cdylib under `#[cfg(target_os="android")]`. Rejected: `uniffi` (MPL-2.0, heavier codegen) [F licence].
- [U] Exact cdylib name from the template (`<crate>_lib`) and whether `WryActivity` has already loaded it — verify in S12.
- Notifications: `NotificationCompat` + `MessagingStyle`, actions Mark read / Reply (`RemoteInput`) / Delete / Copy OTP, handled by `NotificationActionReceiver` (works with the UI closed). OTP notifications use `setVisibility(VISIBILITY_PRIVATE)` with a redacted public version. Linux v1: no notifications (archive viewer).

### 6.4 Honest platform limits
- [I] RCS: no public API for third-party apps (Google Jibe); Google Messages keeps RCS chats outside `content://sms`. mySMS sends SMS only; the RCS UI shows imported/seed RCS metadata and the transport switcher offers SIM1/SIM2. Switching default away from Google Messages ends RCS for the user — must be stated on the role-request screen.
- [I] MMS: as default app, mySMS must download MMS itself (`SmsManager.downloadMultimediaMessage`) and parse the PDU (AOSP parser is hidden API; `klinker41/android-smsmms` is archived [F]). Plan: a Rust `mms-pdu` module for m-notification-ind / m-retrieve-conf (text + image parts) in slice S15. Until S15 passes, the app warns that MMS is not supported.
- [U] OEM background restrictions (MIUI, OneUI) can delay receivers; not testable without the owner's phone.

## 7. Translation
[R] v1 = 1:1 Rust port of `translate.ts` (script detection by Unicode ranges + marker words + phrase tables for hi/ur/hinglish/mr/bn/ta/te → en). Zero model download, deterministic, < 50 KB in the binary, identical on Android and Linux.
[R] Deferred (v2, opt-in, Android only): ML Kit on-device translation (`com.google.mlkit:translate 17.0.3` exists [F Maven]) — proprietary Google SDK terms, ~30 MB per language, so it stays behind a setting and outside the Linux build. Bergamot/other NMT rejected for v1: size and Indic coverage unverified [U].

## 8. Linux packaging (CachyOS, user-scoped)
- Build: `npx tauri build --no-bundle` → `src-tauri/target/release/mysms` → copied to `dist/mySMS-linux-x86_64`. Dynamically links `webkit2gtk-4.1` (installed [F]).
- `scripts/install-linux.sh` (no sudo): installs to `~/.local/bin/mysms`, `~/.local/share/applications/mysms.desktop` (`Exec=mysms`, `Icon=mysms`, `Categories=Network;Utility;`, `StartupWMClass=mysms`), icons into `~/.local/share/icons/hicolor/{32x32,64x64,128x128,256x256,512x512}/apps/mysms.png` + `scalable/apps/mysms.svg`; runs `update-desktop-database ~/.local/share/applications` and `gtk-update-icon-cache` only if present; `--uninstall` removes exactly those paths.
- Wayland and X11 both via GTK; [U] document `WEBKIT_DISABLE_DMABUF_RENDERER=1` only as a troubleshooting fallback (not set by default; AMD GPU here).
- AppImage/deb not needed for this machine; Flatpak deferred.

## 9. Signing plan
- Keystore at `~/.config/mysms-signing/mysms-release.jks`, properties file `~/.config/mysms-signing/keystore.properties` (mode 0600, dir 0700) — outside git. `gen/android/app/build.gradle.kts` reads `MYSMS_KEYSTORE_PROPERTIES` (default that path); missing file → release build fails loudly (no silent debug signing for `dist/`).
- Keystore creation is an **owner-run** script (`! bash scripts/make-keystore.sh`): RSA 4096, validity 10000 days, random password written straight into the 0600 file, never echoed. Owner must back the keystore up: losing it means no updates to the installed app [F general Android signing].
- Verify: `apksigner verify --print-certs dist/mySMS-arm64.apk`.

## 10. Security and privacy
- Zero network: CSP `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self'; connect-src ipc: http://ipc.localhost`. No INTERNET permission in the Android manifest unless Tauri's template requires it for dev [U: check in S11; strip from release if possible].
- Remove `@google/genai`, `express`, `dotenv` from package.json (not imported anywhere [F grep]); remove Google Fonts `<link>` from index.html (network leak) → self-hosted fonts.
- Tauri capabilities: least privilege per platform (`core:default`, `dialog:allow-open/save` on Linux, `telephony:*` on Android). No shell, no fs scope beyond app data.
- No logs of message bodies or OTPs (`tracing` off in release; debug logs redact).
